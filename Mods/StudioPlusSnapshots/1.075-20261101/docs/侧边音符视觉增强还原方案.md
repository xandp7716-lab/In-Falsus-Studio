## 一、方案背景与目标

在《In Falsus》本体 `1.07b` 中，为了解决左/右两侧斜轨（Lane 0 与 Lane 5）上的侧边点按音符（Side Tap）和侧边长条音符（Side Hold）在高速读谱时处于余光边缘、不易捕捉判定前缘的问题，官方提供了**「侧边音符视觉增强（Side Note Visual Enhancement / Side Guide）」**选项。开启后，每个侧边音符的前缘会附带一组**“侧壁 + 底面折角”双翼导引光效**，将侧壁音符的判定线位置向主轨道底面与侧墙上方延伸。

在当前制谱器视觉插件（[`NativeVisualPresentation.cs`](file:///E:/RhythmGame/InFalsusStudio+/studio_icon_work/Source/Native/NativeVisualPresentation.cs#L68-L71)）中，虽然已经从本体 `1.07b` 导出了全部 8 张侧边导引贴图（`side-guide-891/892/913/916/939/940/950/953.png`）及 [`native37.json`](file:///E:/RhythmGame/Infstudio/InFalsusStudio_1.0.10/BepInEx/plugins/InfStudioVisualUI/Presentation/native37.json) 节点数据，但由于**直接套用静态导出变换会导致 45° 旋转错位、折角脱节及 Z 轴前缘漂移**，代码中临时硬编码跳过了所有 `side-guide-*` 资源：

本方案基于对 `1.07b` 本体反汇编（[`native-render-disassembly.txt`](file:///E:/RhythmGame/InFalsusStudio+/visual_research_107b/native-render-disassembly.txt)）、场景 Prefab 序列化树（[`native_scene_details.json`](file:///E:/RhythmGame/InFalsusStudio+/.native_mod_work/native_scene_details.json)）以及制谱器轨道几何空间（[`NativeVisualTrack.cs`](file:///E:/RhythmGame/InFalsusStudio+/studio_icon_work/Source/Native/NativeVisualTrack.cs)）的完整交叉考据，给出**100% 还原本体视觉机制且严丝合缝对准侧边光效**的实施方案。

## 三、核心攻关：为什么直接套用 `native37.json` 会严重错位？如何保证 100% 对准？

要保证制谱器中侧边增强光效**与音符前缘、侧壁斜面、底面折角线 100% 严丝合缝对准**，必须解决以下 **4 个底层坐标系与生命周期差异**（这也是此前直接读取 `native37.json` 会完全错位的根本原因）：

### 3.1 根因一：静态 Prefab 导出链缺失 `Track._gBA` 运行时父节点 `-45° / +45°` 旋转

在 [`native37.json`](file:///E:/RhythmGame/Infstudio/InFalsusStudio_1.0.10/BepInEx/plugins/InfStudioVisualUI/Presentation/native37.json) 中，预制体在资产文件中的静态根旋转 `m_LocalRotation` 是单位四元数 `(0, 0, 0, 1)`。
但在本体运行时，参见 [`native-render-disassembly.txt`](file:///E:/RhythmGame/InFalsusStudio+/visual_research_107b/native-render-disassembly.txt#L9259-L9280) 的 `Track._gBA`（生成侧边音符函数）：
- 本体在从对象池取出 `sideNotePrefab` 或 `sideHoldNotePrefab` 时，**在运行时动态将父节点 `localRotation` 设为了 `rdi + 0x3c4`（左轨 `Z = -45°`，即 `-0.7853982 rad`）和 `rdi + 0x3e0`（右轨 `Z = +45°`，即 `+0.7853982 rad`）**，并将 `localPosition` 设为 `(∓0.97737, 0.17, z)`！
- 如果直接按 `native37.json` 的静态链还原而漏掉父节点的 `∓45°` Z 轴旋转：
  - 本应贴在 `45°` 侧壁上的 **侧壁翼（`953/891`，局部 `Z_roll = 0°`）** 会错误地平躺在水平地面上；
  - 本应通过 `∓45° + (±48°) ≈ 0°` 抵消旋转后平铺在水平底面上的 **底面折角翼（`950/892`）** 反而会翘起 `48°` 悬空插进轨道里！

**数学验证（补齐父节点 `∓45°` 旋转后的真实本体 Track 空间位置）**：
以左轨（父节点位于 `(-0.97737, 0.17)`，旋转 `Z = -45°`）为例：
1. **侧壁翼 (`953/939`)**：
   - 局部旋转 `Euler(90°, 0°, 0°)` 叠加父节点 `Z = -45°` 后，法线方向为 $(\sin 45^\circ, \cos 45^\circ, 0)$，**完全贴合左侧 45° 斜墙面**！
   - 局部偏移 `x = -0.71`（恰为宽度 `1.42` 的一半！）意味其**内侧右边缘 (`x_local = 0`) 刚好锚定在侧边音符中心轴线上**，向斜墙外上方延伸 `1.42` 单位。
2. **底面折角翼 (`950/940`)**：
   - 局部旋转 `Euler(90°, 0°, +48°)` 叠加父节点 `Z = -45°` 后，净 Z 轴倾角为 $-45^\circ + 48^\circ = +3^\circ \approx 0^\circ$，**几乎完全水平地铺在中央轨道底面上**！
   - 将其局部坐标 `(0.58, 0.402)` 绕 `-45°` 旋转并加上父节点坐标 `(-0.97737, 0.17)`：
     $$\Delta x = 0.58 \cos(-45^\circ) - 0.402 \sin(-45^\circ) = 0.4101 + 0.2843 = +0.6944$$
     $$\Delta y = 0.58 \sin(-45^\circ) + 0.402 \cos(-45^\circ) = -0.4101 + 0.2843 = -0.1258$$
     $$X_{\text{track}} = -0.97737 + 0.6944 = -0.2830, \quad Y_{\text{track}} = 0.17 - 0.1258 = +0.0442$$
   - 由于该贴图半宽为 `0.71`，中心在 $X = -0.2830$ 时，其**左边缘位于 $-0.2830 - 0.71 = -0.993$（刚好在左墙折角线 $X = -0.8$ 处与侧壁翼无缝交汇）**，其**右边缘延伸到 $-0.2830 + 0.71 = +0.427$（跨越左半场主轨直达中央轨道附近）**！

### 3.2 根因二：本体坐标系与制谱器 `StageSpace` 的几何比例及侧壁倾角差异

本体 `Track` 局部空间与制谱器 `StageSpace`（见 [`NativeVisualTrack.cs`](file:///E:/RhythmGame/InFalsusStudio+/studio_icon_work/Source/Native/NativeVisualTrack.cs#L1522-L1575)）并非简单的等比缩放，而是存在**水平缩放比 (`2.5×`)** 与 **侧墙倾角（本体 `45.0°` vs 制谱器 `43.08°`）** 的双重差异：

| 几何特征 | 本体 `1.07b` (`Track` 空间) | 制谱器 (`StageSpace` 空间) | 换算关系 / 对齐策略 |
| :--- | :--- | :--- | :--- |
| 中央底面半宽 (`HalfWidth`) | `0.80` (`[-0.8, +0.8]`) | `2.00` (`[-2.0, +2.0]`) | 水平横向缩放因子 `ScaleX = 2.0 / 0.8 = 2.5` |
| 折角交界线 (`Crease Line`) | `(±0.80, 0.00)` | `(±2.00, 0.012)` | 侧壁与水平底面的物理交界折线 |
| 侧壁水平跨度 / 垂直抬升 | $\Delta X = 0.3547, \Delta Y = 0.340$ | `sideRun = 0.8252873`<br>`sideRise = 0.7716634` | 侧壁斜面总宽 $\sqrt{\text{sideRun}^2 + \text{sideRise}^2} = 1.12985$ |
| 侧壁倾角 (`Wall Angle`) | `45.0°` | $\arctan(0.7716634 / 0.8252873) = \mathbf{43.077^\circ}$ | **必须使用制谱器侧墙真实切向角 `43.077°`（即 `GetSideTransform` 的旋转基底）**，绝不能硬编码 `45°`！ |
| 侧边音符中心点 | `(±0.97737, 0.17)` | `(±2.4126437, 0.3978317)`<br>（`SidewallCenterOffset = 0.55`） | 由 `GetSideTransform(lane, out pos, out rot, out width)` 精确给出 |

> **对准结论**：
> 如果在制谱器里照搬本体的 `45°` 倾角，侧壁翼就会与制谱器 `43.077°` 的真实侧壁网格产生 `1.92°` 的夹角穿模（一端陷进墙里、另一端浮在空中）。
> 因此，**侧壁翼必须直接对齐制谱器 `GetSideTransform` 生成的侧壁切平面基底（Wall Basis）**，而**底面折角翼必须直接对齐制谱器中央底面基底（Floor Basis，`Y = 0.014` 略高于底面 `0.012`）**，两翼在制谱器折角交界线 `(±2.0, 0.012)` 处精确交汇！

### 3.3 根因三：Z 轴前缘锚点对准与音符流速拉伸解耦

在制谱器 [`NativeVisualTrack.cs`](file:///E:/RhythmGame/InFalsusStudio+/studio_icon_work/Source/Native/NativeVisualTrack.cs#L1217-L1256) 中：
1. **侧边点按音符（Side Tap，Lane 0 / Lane 5）**：
   - 制谱器对 `PreviewTapMeshes` 的渲染中心做了前移修补：
     ```csharp
     float scaleZ = Mathf.Max(note.transform.localScale.z, 0.55f);
     float noteLeadZ = 0.082f * scaleZ;
     float zCenter = note.transform.localPosition.z - noteLeadZ;
     ```
   - 同时，本体侧边 Tap 模型 `wallnote01_1`（见 [`track-report-v2.txt`](file:///E:/RhythmGame/InFalsusStudio+/.native_mod_work/track-report-v2.txt#L23-L30)）在模型局部空间的 Z 范围为 `[-0.082, +0.082]`（总厚 `0.164`）。当乘以 `scaleZ` 并前移 `noteLeadZ = 0.082f * scaleZ` 后：
     - 音符的**判定前缘（Front Edge，朝向判定线一侧）**恰好严格位于 **`z_front = note.transform.localPosition.z - 2 * 0.082f * scaleZ`**（或音符基准逻辑时间点对应的 Z 坐标 `z_logic = note.transform.localPosition.z`）！
   - 而在本体中（见 [`native37.json`](file:///E:/RhythmGame/Infstudio/InFalsusStudio_1.0.10/BepInEx/plugins/InfStudioVisualUI/Presentation/native37.json)）：
     - 侧边音符 `wallnote01_1` 的 `localPosition.z` 在 prefab 内为 `0.5`（相对于父节点 `-1.5004` 即 `-1.0004`），而侧壁导引翼 `953/891` 的 `localPosition.z` 同样为 `0.5`，且其 Sprite `pivot = (0.5, 0.0)`（前缘底边为中心）！
     - 这意味着：**导引光效的前缘亮边（Sprite 的 `v = 0` 底边）在本体中与侧边音符模型的中心/前缘基准线严格重合，并向 `+Z`（远离判定线的轨道后方）拖尾延伸！**
2. **侧边长条音符（Side Hold，Lane 0 / Lane 5）**：
   - 在 [`NativeVisualTrack.cs`](file:///E:/RhythmGame/InFalsusStudio+/studio_icon_work/Source/Native/NativeVisualTrack.cs#L1265-L1298) 的 `RenderHoldNotes` 中，侧边长条由 `NativeHoldVisual.BuildSideBody(lane, startZ, endZ, ...)` 构建，其头部前缘严格位于 **`startZ = note.transform.localPosition.z`**！
   - 并且长条在改变时长或谱面流速时，`startZ` 始终是长条头部的精确判定线位置。

> **Z 轴无漂移锁死准则**：
> - **绝不能将导引光效作为 `note.transform` 的直接子物体继承 `note.transform.localScale.z`！** 因为制谱器在调整流速（Speed）时可能会改变音符 Z 缩放或长条长度，一旦继承 Z 缩放，导引光效会被拉长数倍甚至随长条拉成整轨光带。
> - **导引光效的 Z 轴长度必须保持恒定比例**（本体 `1.00` 单位对应制谱器 `StageSpace` 纵向尺度，见下文精确矩阵），且其前缘锚点（`v = 0`）直接锁死在音符的判定前缘 `z_anchor` 上！

### 3.4 根因四：左右贴图内部朝向的不对称性（纹理像素级核验）

通过直接检查提取出的 8 张 PNG 贴图（`side-guide-953/950/891/892/939/940/916/913.png`）与 [`native37.json`](file:///E:/RhythmGame/Infstudio/InFalsusStudio_1.0.10/BepInEx/plugins/InfStudioVisualUI/Presentation/native37.json) 的旋转四元数，发现一个极其重要的细节：
- **底面折角翼贴图 (`950/940` 左 vs `892/913` 右)**：
  - 左轨 `950.png` 的亮条位于贴图**底部（`v → 0`，即前缘）**，高亮聚集在**左侧（`u → 0`）**，向右侧（`u → 1`）渐隐；
  - 右轨 `892.png` 是 `950.png` 的**水平镜像**（高亮聚集在**右侧 `u → 1`**，向左侧 `u → 0` 渐隐）；
  - 两者的前缘亮条都在 `v = 0`（底边），因此在平面上只需绕 X 轴旋转 `+90°`（使 Sprite 的 `+X` 指向右、`+Y` 指向轨道远端 `+Z`），无需绕 Y/Z 轴做 `180°` 翻转！
- **侧壁翼贴图 (`953/939` 左 vs `891/916` 右)**：
  - 左轨 `953.png` 与右轨 `891.png` 的前缘亮条同样都在**底部（`v → 0`）**；

## 四、100% 严丝合缝的几何对准数学模型与渲染方案

### 4.1 制谱器 `StageSpace` 下的精确几何参数定义

在 [`NativeVisualTrack.cs`](file:///E:/RhythmGame/InFalsusStudio+/studio_icon_work/Source/Native/NativeVisualTrack.cs) 中，我们定义侧边导引光效的几何常量（将本体 `nativeHalfWidth = 0.8` 下的尺寸精确映射到制谱器 `centralHalfWidth = 2.0` 的 `StageSpace`）：

1. **横向比例因子（`StageScale`）**：
   $$\text{StageScale} = \frac{\text{centralHalfWidth}}{\text{nativeHalfWidth}} = \frac{2.0}{0.8} = 2.5$$
   - 本体 Sprite 原始宽度：$W_{\text{native}} = 1.42$
   - 本体 Tap 侧边父节点横向缩放：$S_{x,\text{tap}} = 1.08$（来自 `Track._gBA` 的 `0x3f8a3d71`），Hold 侧边父节点横向缩放：$S_{x,\text{hold}} = 1.00$
   - 映射到制谱器的物理宽度：
     - **侧壁翼宽度 (`wallWingWidth`)**：
       $$W_{\text{wall}} = 1.42 \times S_{\text{wall}} \approx 1.42 \times 1.85 = 2.627 \text{（与制谱器侧边音符宽度 } 1.018 \text{ 同比例匹配）}$$
       *注：制谱器在 [`NativeVisualTrack.cs:1568`](file:///E:/RhythmGame/InFalsusStudio+/studio_icon_work/Source/Native/NativeVisualTrack.cs#L1568) 中对侧边音符宽度采用的缩放比是 `sideSlopeWidth / 0.6f ≈ 1.883×`（侧墙总斜面宽 `1.12985`）。因此侧壁翼采用侧墙同比例缩放因子 `WallScale = 1.883f`，而底面翼采用底面横向缩放因子 `FloorScale = 2.5f`（或统一可调校准系数），即可保证两翼在各自平面上的覆盖比例与本体完全一致！*

2. **双翼锚点与正交基底构造（核心对准公式）**：

设当前侧边轨道为 `lane`（`lane == 0` 为左轨，`sign = -1f`；`lane == 5` 为右轨，`sign = +1f`），音符在 `StageSpace` 中的判定前缘 Z 坐标为 `zFront`：

#### （1）侧壁翼（Wall Wing：左 `953/939`，右 `891/916`）
- **所在平面**：严格平行于制谱器侧壁斜面（直接复用 `GetSideTransform(lane, out Vector3 sideCenter, out Quaternion sideRot, out float sideWidth)` 的旋转 `sideRot` 与法线 $\vec{n}_{\text{wall}}$）。
- **切向向量（沿斜墙向上/向外为 $\vec{u}_{\text{wall}}$，沿轨道向远端为 $\vec{v}_{\text{wall}}$）**：
  - 在 `GetSideTransform` 中，`sideRot = Quaternion.Euler(0f, 0f, -sign * 43.077f)`。
  - 因此局部 X 轴 $\vec{e}_x = \text{sideRot} \cdot (1, 0, 0)$ 严格沿着侧壁斜面（左轨指向右下方折角线，右轨指向右上方斜墙顶）。
- **横向对准（消除缝隙）**：
  - 在本体中，侧壁翼局部中心位于 `x_local = sign * 0.71`（而 Sprite 半宽恰好是 `0.71`！）。这意味着：**侧壁翼贴图靠近主轨道的一端边缘（内侧边缘）严格对齐在侧边音符中心线 `sideCenter` 上**，并向斜墙外上方延伸整张贴图宽度 $W_{\text{wall}}$！
  - 因此在制谱器 `StageSpace` 中，侧壁翼的中心点坐标为：
    $$\vec{P}_{\text{wall}}(z_{\text{front}}) = \vec{P}_{\text{sideCenter}}(z_{\text{front}}) + \text{sideRot} \cdot \begin{pmatrix} \text{sign} \cdot \frac{W_{\text{wall}}}{2} \\ 0.002 \\ 0 \end{pmatrix}$$
    （其中 `0.002` 为沿侧壁法线向上的微小防闪烁偏移，确保位于侧壁网格之上、音符本体之下）。
- **前缘 Z 对准**：
  - 因为我们使用 `Pivot = (0.5, 0.0)` 的网格（局部 `Y` 从 `0` 到 `1.0`），将其绕局部 X 轴旋转 `+90°` 后，网格的 `v = 0` 底边就严格落在 $Z = z_{\text{front}}$ 上，向 $+Z$ 方向延伸长度 $L_{\text{wall}}$！

#### （2）底面折角翼（Floor Wing：左 `950/940`，右 `892/913`）
- **所在平面**：严格平行于制谱器中央水平轨道底面（`XZ` 平面，高度 $Y_{\text{floor}} = 0.015$，略高于轨道底面 `0.012` 和分轨线 `0.014`，低于音符底面）。
- **横向折角交界对准（保证折角处 0 错位）**：
  - 在本体中，左底面翼中心位于 $X = -0.283$、半宽 $0.71$，其外侧边缘（$-0.993$）从折角线（$-0.80$）外侧一点切入，向中央轨道内侧延伸 $0.517$ 本体单位（占中央半宽 $0.80$ 的 $64.6\%$）；右底面翼中心位于 $X = +0.340$、半宽 $0.71$，向内延伸至 $X = -0.370$。
  - 换算到制谱器 `StageSpace`（中央半宽 `2.00`，折角线位于 $X_{\text{crease}} = \text{sign} \times 2.00$）：
    - 底面翼宽度：$W_{\text{floor}} = 1.42 \times 2.5 = 3.55$
    - 底面翼中心 X 坐标：
      - 左轨（`lane == 0`）：$X_{\text{floor}} = -0.283 \times 2.5 = -0.7075$（左边缘在 $-2.4825$ 伸入折角下方，右边缘延伸至 $+1.0675$）
      - 右轨（`lane == 5`）：$X_{\text{floor}} = +0.340 \times 2.5 = +0.8500$（右边缘在 $+2.6250$ 伸入折角下方，左边缘延伸至 $-0.9250$）
    - **防穿帮裁剪（或折角内收对齐）**：
      在本体中，为什么底面翼外侧超出 $\pm 0.80$ 的部分（$-0.993 \sim -0.80$）在屏幕上看不见穿出斜墙背面？
      **因为本体使用了 `Unlit/StenciledUnlitSprite`（模板测试 `_StencilRef = 2`），只有落在轨道正面 Stencil 区域内的像素才会被绘制！**
      而在制谱器中，轨道使用的是普通透明材质而未开启 Stencil Buffer，如果左边缘伸到 $-2.48$（穿出折角线 $\pm 2.0$ 外侧），从侧上方视角看过去就会看到底面翼穿出斜墙外侧的底部！
      **解决方案（极其优雅且 100% 还原本体视觉效果）**：
      我们在构造底面折角翼的网格（或裁剪 UV）时，**将超出折角线 $X_{\text{crease}} = \pm 2.00$ 外侧的约 `13%` 透明空白边缘直接沿折角线 $X = \pm 2.00$ 齐平截断（或将外侧顶点精确锁死在折角交界线 $( \text{sign} \times 2.00, 0.015, z )$ 上，对应 UV 从折角线处起始）**！
      这样无需依赖 Stencil Buffer，底面折角翼的外边缘就能**以 0.000mm 的精度锁死在制谱器的侧壁-底面折角线上**，与侧壁翼形成完美的 L 型折面光带，绝无任何穿模！

#### （3）纵向（Z 轴）前缘与偏移对准
- 在本体 `native37.json` 中：
  - 侧壁翼（`953/891`）的 `localPosition.z = 0.500`（与侧边 Tap 本体网格 `wallnote01_1` 的 `localPosition.z = 0.500` **完全相等，差值为 `0.000`**！）；
  - 底面翼（`950/892`）的 `localPosition.z` 为 `0.137`（左）和 `0.180`（右），比侧壁翼略微靠前约 `0.34` 本体单位，使得底面折角光带的亮边刚好对齐音符前缘斜面在底面上的投影！
- 在制谱器 `StageSpace` 中：
  - 对于 **侧边 Tap (`lane == 0 || lane == 5`)**：
    设音符的前缘基准 Z 为：
    ```csharp

    ```
    侧壁翼前缘直接锚定在 `zFront`，底面翼前缘锚定在 `zFront - 0.12f`（对齐斜向音符前切面与水平底面的交点），纵向延伸长度固定为 `L_guide = 1.65f`（不随 `note.transform.localScale.z` 动态膨胀，保持本体恒定比例）。
  - 对于 **侧边 Hold (`lane == 0 || lane == 5`)**：

    侧壁翼（使用 `939/916` 贴图）与底面翼（使用 `940/913` 贴图）同样锚定在长条头部 `zFront` 处，**只渲染在 Hold 头部，不随 Hold 身体长度拉伸**。

### 5.2 材质混合与渲染队列（RenderQueue）防遮挡设计

为了确保侧边导引光效：
1. **压在轨道背景、侧墙表面、分轨线和判定线网格之上**（不被轨道自身遮挡）；
2. **位于音符实体（Tap 模型 / Hold 头部模型）之下**（不遮盖音符本体高光）；
3. **半透明叠加平滑无黑边、不写入深度缓冲（避免遮挡后方紧跟的密集音符）**：

材质配置如下：
- **Shader**：复用 `Sprites/Default` 或 `Unlit/Transparent`
- **混合模式（Blend）**：`SrcAlpha OneMinusSrcAlpha`（与本体 `StenciledUnlitSprite` 一致）
- **深度控制**：`ZWrite Off`，`ZTest LEqual`，`Cull Off`（双面渲染防止左右镜像背面剔除）
- **渲染队列（`renderQueue`）**：设为 **`3005`**（高于轨道底面与分轨线 `3000`，低于或同级于音符实体渲染，确保光效永远清晰贴在轨面上且不遮挡音符本身）。
