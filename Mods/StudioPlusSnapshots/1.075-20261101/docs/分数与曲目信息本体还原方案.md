# 分数栏与曲目信息栏本体还原方案

日期：2026-11-01。目标本体：`E:\RhythmGame\InFalsus\InFalsusModded1.07b`。目标制谱器：Studio+ 1.0.7。本文只制定方案，未修改、编译或安装制谱器。

## 1. 结论与还原范围

应将当前“贴底图 + 预烘焙数字 + GDI 字体”的 HUD 绘制替换为本体的布局参数、FastText 字形与渲染语义。只改几个字号、色值或截图切片，不能达到所要求的还原度。

还原对象是正常游玩中的 ScoreContainer 与 SongInfoContainer，包括边框/底板、分数及阴影、SCORE、曲绘、曲名/作者及阴影、难度底板/文字/等级、SPEED/速度、内嵌进度线。制谱器独有的播放按钮、编辑命中区与输入草稿继续作为编辑功能保留；它们不冒充本体部件。

“完全还原”作为实现及验收目标：相同资源、数据、视口和后处理条件下对齐。本文已有明确的本体参数依据，但尚未实现或做同帧渲染对比，因此不能宣称当前已像素一致。不同 Unity/URP 版本的采样、后处理及字体管线仍须通过实际渲染验收。

用户截图用于识别当前差异，不作为资源提取或坐标测量来源。

## 3. 坐标与布局规则

本体 CoreScene.Update（RVA 0x6E8650）设置逻辑 UI 尺寸 3840×2160，并根据显示比例调整相机视口。以下均为本体序列化的 Constrained2D 参数，不是截图像素。

- 左上 ScoreContainer：parentAlignment=5，offset=(0,0)。右上 SongInfoContainer：parentAlignment=6，offset=(0,0)。两者不能按窗口中央或歌曲标题宽度反推位置。
- 表内 Y 正方向向上；offset.Y 为负表示向下。普通文本 alignment=3（Left）；等级 alignment=4（Center）。文本定位点不是“可见字形左上角”。
- 在标准 1920×1080 有效视口下，3840 逻辑单位的尺寸按 1/2 映射；但可见字形位置还必须经过字体 bearing、alignment、C2D、层级和 Z 投影。不能简单将 offset/2 当作 GUI.Label 的左上角。
- 实现要复现 CoreScene 的有效视口及 C2D 变换，再将结果绑定制谱器 ViewCamera.pixelRect。黑边、非 16:9 和窗口缩放必须基于有效视口，不基于整个桌面。
- 本次采样本体客户区为 2048×1152。有效运行时变换已保存，不再需要用户保持游玩。

## 5. 分数绘制与数据更新

分数格式保留九位补零及 ASCII 撇号分组，例如 003'720'851、100'000'000；不可换成逗号、弯引号或用等宽占位替代字体度量。

本体 ScoreContainer._pCA（0x68F2D0）在分数上升时，对 scoreText 两层调用原生数值更新工具 _qi._TqA（0x50CE30），传入 0.5 秒参数，并取消原有 tween。因此实现中需要区分数值来源和显示动画：

- 编辑器仍使用当前 PreviewScore/实测 ScoreEvidence 作为数据源，本次不重写判定、得分或物量算法。
- 正常连续播放的递增显示对齐本体的数值更新/取消/格式化路径；0.5 秒是传入值，具体插值/取整必须移植该函数，不能自行改成“每帧 lerp 一下”。
- 拖动时间、倒退、切谱、改物件时立即同步当前分数并清空旧动画，防止半秒旧数字滞留。这是制谱器的编辑适配，不改变本体成绩计算。
- 主字和阴影必须在同一帧、同一显示数值上更新。本次读取是顺序采样，日志中两层不同数字不能当成应保留的本体时间差。
- 字形及网格按实际字符串变化更新；每帧只更新动画和必要的材质参数，不逐帧创建贴图、注册字体或分配一整套 GUI 对象。

## 6. 长曲名、作者与进度线

SongInfoContainer._qCA（0x68F5C0）负责标题/作者文本、字库、难度、曲绘及标题滚动；_QCA（0x68F460）负责进度表现。

已确认的长标题分支：

- 测量标题实际 C2D 宽度 W，excess=max(W-620,0)，单位为本体逻辑像素。
- excess≤30：AnimationOffsetContainer 位移归零，不滚动。
- excess>30：SongTitleContainer X 初始设置为 -excess/2，并调用 SmallSongCard._Fy（0x59C2D0），速度参数为 50。
- _Fy 内使用 excess/50 以及额外 2.650000095 的时间项构造动画。该时间项是原函数的构造参数，不直接臆测为完整往返周期；起停、回程、缓动与等待按原更新回调一并移植。
- SongTitleMask 的 invertMask=1，目标是标题及标题阴影；必须还原原遮罩语义，不能按“1 表示隐藏标题”猜测。
- 作者使用自己的固定字号与原遮罩/布局关系，不擅自复制标题滚动或强行缩成一行；长作者和多语言另列验收。

编辑适配：点击曲名编辑时暂停标题位移动画，输入层使用固定可编辑命中框；提交/取消后从一致状态恢复。显示文字、输入光标和点击区域不可各自偏移。

内嵌进度线保留本体左右端点、材质和光点随比例移动的逻辑。现有鼠标拖动进度、悬浮时间戳、鼠标移出隐藏及外置进度条选项继续保留；时间戳是编辑辅助，不混入本体 HUD 原始材质。曲名/作者区域的点击不得被进度条扩大命中区截走。

## 7. 渲染实施方案

### 7.1 资源及文字

新增专用 NativeHudLayout / NativeHudText / NativeHudRenderer 适配模块；实际名称可按项目约定调整。资源按当前本体 scene/material/font 重新导出，记录原对象 ID、SHA-256 和材质参数。当前原生场景包已核验为 51B280F15EEE8EE0DCD8B35929896F85390471D5ABFDAA573C7A474343552011，与本次读取的场景数据一致。

实现本 HUD 所需的 FastText 字形度量、kerning、对齐、字库回退、SDF 采样、SplitColors、Mask 与公共参数缓冲语义。动态中文/日文不能靠预烘焙少数字符覆盖。继续使用本体原始字体字节及原生着色器逻辑；不把 GDI 的 getlength、手工 advance 或截图裁切作为最终依据。

### 7.2 HDR、Gamma 与 Bloom

本体 PlayerSettings 是 Gamma；当前制谱器的场景是 Linear，不能直接照搬 RGB 数字到现有 IMGUI 并期待结果一致。

本体 CoreScene 的 Volume 配置：Bloom threshold=1.5、intensity=2.0、scatter=0.820999980、clamp=65472、skipIterations=1、maxIterations=6、highQualityFiltering=0；tint=(1,1,1)，dirtIntensity=0。Tonemapping.mode=0；曝光、对比度、色相、饱和度调整均为 0。具体启用条件仍需沿用本体相机/Volume 的实际关系，不能只凭某个参数存在就全局开启。

推荐把本体 HUD 的颜色合成和后处理隔离到专用渲染路径：

1. 从编辑器有效视口取得正确时点的背景，按本体 Gamma 语义合成原生 HUD；中间使用至少 RGBAHalf，保留超过 1 的能量。
2. 使用本体 HUD 所需的 SDF/遮罩及相同 Bloom 算法和参数；保留边框原透明合成关系。
3. 在明确的颜色空间转换点回到编辑器显示。可用背景基准与“背景+HUD”两次结果的差分合成，避免对已有舞台再次应用一遍本体后处理；差分的负值必须在有符号浮点中保留。该方案是实现设计，不是声称本体本身采用此两遍方式。
4. 只替换 HUD 贡献，保留编辑器背景、轨道、音符、网格和其他面板原有渲染。不能为了分数发光改全项目 Gamma、全局曝光或舞台 Bloom。
5. 发光溢出范围按实际卷积核保留，不能把一个小框剪裁后截掉光晕，也不能将宽屏边界当成整张 UI 底图拉伸。

若隔离管线与直接原生路径仍有可见差异，必须按原生同背景对照继续修，不能以“已用了原字体”作为还原完成标准。HUD 在不同背景上的合成结果应一起验收。

### 7.3 保留编辑行为

替换 NativePresentation.DrawHud / Digits / InkText 的显示职责，并由统一布局结果更新 Layout、NativeHudControls、HUD 字段编辑和 NativeProgress 的命中坐标。

必须保留当前 DrawSongHud 的非 Repaint 分支、控制 ID、一致的 Layout/输入控件树、手动保存、草稿提交/取消、撤销边界。不能用新的可见控件插入 Repaint 分支导致底部输入框焦点或 Tab 网格热键回退。

不顺带修改分数算法、曲目元数据、音频偏移、滚速含义、判定线、按键贴图或舞台视距。已有 AP 顶部条和播放按钮仍为独立模块，不将它们混入这两个本体容器。

## 8. 执行顺序和验收

1. 固定本体资产/字库/材质及参数清单，先完成原生布局与静态底板；移除该 HUD 路径上的 HSV 近似底板。
2. 对齐文本字形、度量、位置、主字/阴影，再做 HDR 分色与 Bloom；不在文字仍错误时用模糊掩盖。
3. 补上分数更新、长曲名遮罩/滚动和进度表现。
4. 接回原编辑交互，再进行渲染与编辑回归。只有用户授权执行后才修改副本；本次不实装。

验收矩阵：

- 1920×1080、1280×720、2560×1440、此次本体 2048×1152，以及非 16:9 有黑边的有效视口；四角锚点和字体比例稳定，不对底图进行非等比伸缩。
- 分数 000'000'000、001'111'111、088'888'888、099'999'999、100'000'000；检查 1/8/撇号的间距、上下分色、阴影和光晕。
- 四种难度、等级含加号/小数（以本体支持的真实格式为准）、速度 3.00/5.00；标题 Outliers 作为短文本基准，再测长标题、中文/日文及混合字符。
- W≤620、620<W≤650、W>650 三段标题宽度边界；遮罩不可压暗曲绘、小字或进度线。
- 暂停、连续播放、时间倒退、切谱、点击标题/作者编辑、提交/取消、拖动进度、时间戳移出隐藏、Tab 连续切网格，均不得回退。
